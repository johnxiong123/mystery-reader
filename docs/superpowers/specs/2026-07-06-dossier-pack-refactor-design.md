# 「卷宗包」重构 — 设计文档

> 日期：2026-07-06
> 目标：让真实用户零门槛用上 mystery-reader——打开网页即读，无安装、无 API Key、无自备书源。
> 来源：一轮第一性原理 brainstorm（产品层 + 架构层），关键决策均经用户确认。

## 1. 第一性原理推导（为什么重构）

**产品目标**：真实用户用起来（用户已确认，非作品集/作业）。

**现状与目标的矛盾**：当前形态是 macOS 本地 app，用户需要①下载安装、②自备 OpenAI 兼容 API Key、③自备 txt/epub 书源。三堵墙叠加，真实读者转化率≈0（同类开源项目如 DaviRain-Su/empty 仅 15 star 印证此模式跑不通）。

**核心洞见**：现有不变量"AI 仅在导入时调用"意味着**同一本书的抽取结果对所有读者完全相同**——抽取是内容生产，阅读是内容消费，两者时间上天然分离，可以物理解耦。一次抽取，万人使用。

**推论**：把"抽取"从用户侧挪到生产侧（维护者离线跑），产品对用户就变成纯静态内容站——三堵墙同时消失。

## 2. 已确认的关键决策

| 决策点 | 结论 | 理由/备注 |
|---|---|---|
| 产品方向 | 方案 A：卷宗包 + Web 阅读端 | 用户选定；B（在线服务垫付 API 费）成本无上限不现实，C（继续本地 app）与目标矛盾 |
| 内置书目内容 | **AI 自译公版原著** | 公版仅覆盖原著，现代中文译本有译者版权不可用；AI 译文自产自用无第三方版权 |
| 移动端 | **首发只做桌面 Web** | 用户选定；移动优先重设已知是长期正确方向，列入下期（风险已提示：阅读主场在手机） |
| 协作模式 | fable5 写 spec/计划/验收调试，轻量模型子代理执行 | 用户指定 |
| 部署 | GitHub Pages（静态） | 免费、与 repo 一体 |

## 3. 总体架构

```
tools/pack-producer/     内容生产 CLI（维护者本地跑，用维护者的 Key）
  原文txt → 术语表生成 → AI逐章翻译 → AI抽取(复用现有extractor语义) → 质检 → 卷宗包
packs/                   卷宗包产物（静态 JSON）
web/                     阅读端（新增 DataSource 适配层；新增静态构建目标；部署 GitHub Pages）
server/                  保持不动（本地全栈模式继续可用，"自带书+Key"路径不受影响）
```

### 3.1 卷宗包格式（pack format）

一书一目录：`packs/<book-slug>/`
- `manifest.json`：书元数据（title/author/原著语言/译者="AI 翻译"/公版依据=作者卒年/章节数/字数/格式版本号 `packVersion`）
- `chapters.json`：`[{ idx, title, content, word_count }]`（中文译文）
- `dossier.json`：`{ characters: [{id,name,aliases,identity,first_seen_chapter}], relationships: [{id,from_char_id,to_char_id,type,reveal_chapter,description}], events: [{id,description,occur_chapter,reveal_chapter,involved_char_ids}] }`
- `glossary.json`：统一译名表（生产工具产物，随包保留供质检/再生产）
- `packs/index.json`：书目索引（书架数据源）

字段语义与现有 SQLite schema 完全一致（`first_seen_chapter`/`reveal_chapter` 防剧透语义原样保留），阅读端逻辑最小改动。格式在子项目①冻结后，②③并行。

### 3.2 pack-producer CLI（内容生产线）

流程五步，每步可独立重跑（幂等、断点续跑）：
1. **分章**：复用 `server/src/ingest/` 现有分章能力。
2. **术语表先行**：全书扫描专有名词（人名/地名/机构），AI 生成统一译名对照表，人工可改。这是长篇 AI 翻译不发生"人名漂移"的核心手段。
3. **逐章翻译**：注入术语表逐章翻译，输出中文 `chapters.json`。
4. **抽取**：对中文译文跑现有抽取 prompt（语义复用 `server/src/ai/`），输出 `dossier.json`。
5. **质检**：
   - 译名一致性脚本：检测同一专名多译名，**0 容忍**（阻断出包）；
   - 防剧透字段完整性：所有实体 `*_chapter` 字段存在且 ≤ 总章数；
   - 人工抽检入口：随机导出 3 章译文供人工过目。

### 3.3 阅读端改造（最小侵入）

- 新增 `DataSource` 接口（`getBooks / getBook / getChapter / getChapterList / getGraph / getCharacter / getTimeline / search / progress读写`），两个实现：
  - `ApiDataSource`：包装现有 `api.js`（本地全栈模式，行为不变）；
  - `PackDataSource`：fetch 静态卷宗包 JSON + 前端过滤。
- **防剧透前移**：把 server 的 `upto` 过滤逻辑（图/档案/时间线/搜索范围/未读章标题隐藏）翻译成前端纯函数模块，**逐条对照 server 实现移植并配单测**。静态站场景下防剧透从安全边界降级为体验设计（数据本来整书可见），可接受。
- 进度/书签：`PackDataSource` 下存 localStorage（保持 current/furthest 双指针语义）。
- 静态版裁剪：无导入、无 AI 设置、无重抽取入口；书架数据来自 `packs/index.json`。
- 构建：Vite 双模式（环境变量切数据源），产物部署 GitHub Pages。

## 5. 量化验收口径

| 指标 | 阈值 | 测法 |
|---|---|---|
| 译名一致性 | 同一专名全书唯一译名，0 容忍 | 质检脚本，CI 阻断 |
| 防剧透 | upto=N 时输出无任何 >N 内容（含标题、搜索片段） | 前端过滤纯函数单测 + 抽查 |
| 零门槛 | 无痕浏览器打开部署 URL → 30 秒内读到正文并看到关系图，全程零配置 | 手动验收 |
| 翻译质量 | 每本随机 3 章人工过目通过 | 用户验收 |
| 现有模式回归 | 本地全栈模式（server + ApiDataSource）行为不变，后端 36 测试全绿 | 全量测试 |

## 6. 子项目分解

| # | 子项目 | 产出 | 依赖 |
|---|---|---|---|
| ① | 卷宗包格式 + pack-producer CLI | 格式冻结文档、CLI 五步管线、质检脚本 | main（已含簇①） |
| ② | 阅读端 DataSource 适配 + 静态构建 + 部署 | 双模式 web、GitHub Pages 上线（可先用 1 本样书） | ①的格式冻结 |
| ③ | 内容生产 | 3 本书卷宗包过质检、译文人工抽检通过 | ①的 CLI |

执行方式：每个子项目 = fable5 写计划 → 轻量模型子代理逐任务执行 → fable5 验收调试。

## 7. 不做（Out of Scope，首发）

- 移动端重设计（下期，已知是正确方向）
- 在线服务/账号体系/多用户
- 阿加莎等未公版书目
- 用户上传书在静态版的支持（本地全栈模式已覆盖该场景）
- 现有 server/桌面 DMG 路径的任何改动
